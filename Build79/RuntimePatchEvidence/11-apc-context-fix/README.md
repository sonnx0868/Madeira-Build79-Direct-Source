# SIGUSR1 context preservation candidate

BeamNG 0.34 Content launch on APC-Signal-v1 mounted all 133 verified content archives and initialized audio, scripts, settings and missions. It then recorded a C++ crash about 25 seconds into startup; the user saw a frozen black window. BeamNG is not playable yet.

The first native fault is a FEX call/return predictor push at PC 0x14ff4648c. Its live x17 unexpectedly equals the preceding PC, 0x14ff46488, so STP attempts to write the guest/host return-address pair into executable code at 0x14ff46478. The existing iOS signal-return helper explicitly sets the interrupted x17 to PC before redirecting through its x18 trampoline. Both source and exact native instructions match. Reproducing that overwrite at the observed instruction boundary produces the same write fault. The exact signal interruption boundary was not event-logged; this is a strongly supported causal match rather than a direct recorded signal trace.

The small JIT dump ranges already contain the overwritten return-address pair. Although the dump was initiated at the first fault, other threads and recovery could proceed during its capture; do not describe the dump as a pristine atomic first-fault snapshot.

This candidate changes one native instruction after SIGUSR1's restore_context, branching to its original epilogue and skipping only the register-clobbering helper. It retains real APC delivery, the complete context save/restore, syscall handling, the TEB-less guard, existing Mach fault recovery, and all prior engine, UI and graphics changes. Other signal handlers are unchanged. No guest-stack write, shared temporary state, or new trampoline is introduced.

This removes the demonstrated x17 corruption but is not a general x18 repair. Darwin can zero x18 on signal return. Existing Mach recovery covers supported direct TEB accesses; indirect copies and some zero-page reads can silently escape that recovery. Current CPU/TLS PE changes reduce dependence on x18 through runtime thread-storage offsets, but do not prove every path. Physical validation must first repeat Wine IO checks and CPU/TLS v6, followed by normal BeamNG Content launch. Those probes provide bounded regression coverage; they do not directly assert TLS immediately after an identified SIGUSR1 on the same worker.

Clock settings remain unchanged. A separate audit found the shared tick counter disabled, but QPC/native timeout clocks use separate paths; this is not established as the current fault's cause.

The native edit is at 0x100100520: e05a00b0 becomes 35000014 (branch to 0x1001005f4). Only three bytes differ in that four-byte instruction. Source and native are paired by verified baseline hashes. Review/test reports describe which actual ARM64 bodies execute and which platform helpers are modeled; no host fixture establishes real Darwin kernel recovery.

The independent fixture and root rerun pass 310 native handler cases plus two generated-code resumption controls. Tests execute the actual handler and save_context/restore_context bodies, with explicit platform/server helper models. The original handler reproduces the exact write protection fault; the candidate preserves x17 and completes that predictor push. Whole-file SHA equality connects the tested synthetic candidate to the packaged native file. These remain host results until the iPad retest.
