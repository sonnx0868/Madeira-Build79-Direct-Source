# Guest process exit: descriptor cleanup correction

The first guest-exit correction kept Madeira and Wine Desktop open on the iPad. Its diagnostic passed graceful exit code 0, then failed because an abrupt child exit requested 0 but Wine reported 1. The last two cases were not executed. That is a partial result, not a completed regression pass.

The saved runtime shows thread 0094 requesting exit code 0, entering the corrected guest-only exit path, and closing descriptor 235 during `ios_fd_cache_release`. Wineserver then reports `request_unixfd=235 errno=9` and a protocol error. Wine's protocol-error path sets the thread exit code to 1.

The exact source and native instructions explain the wrong close. `add_fd_to_cache` stores `fd + 1` so that zero means an empty entry. `get_cached_fd` and `remove_fd_from_cache` subtract one. The iOS process-release routine omitted that subtraction and closed the encoded number. It therefore closed a neighboring descriptor while leaking its own. Cached entries with `FD_TYPE_INVALID` contain an error status rather than a descriptor and must also be skipped. This finding supersedes the initial suspicion of a stale/reused descriptor in this particular trace; the cache representation itself was decoded incorrectly.

`source.patch` corrects the iOS release routine to check the entry type and subtract one before logging and closing. The signed test package applies the same correction to the installed native binary. It replaces the existing 80-byte inner-loop region at `[0x1000f907c, 0x1000f90cc)` in place. The original frame layout, callee-saved registers, slot lookup, cache detachment, outer loop, frees, summary log and epilogue remain intact. The 8192-entry block loop uses bit 16 of its eight-byte offset to detect completion at 65536 bytes. The previous abrupt-exit branch at `0x1000efd98` remains corrected.

Only `Payload/Madeira.app/Madeira` changes from the GuestExit test IPA. All other archive members are compared byte for byte. In particular, the installed CPU/TLS PE fixes and the existing Vulkan, fullscreen and controller payloads are preserved. This does not constitute a new gameplay or controller validation.

Validation completed:

- 92 executions of the complete original or patched native release routine in Unicorn. Cases cover absent and released caches, the last cache slot, descriptor 0, the first and last entries of blocks 0 and 127, sparse blocks, cached errors, all five-bit nonzero type values, and deterministic mixed entries. The fixtures check closed and logged descriptor values, cache detachment, freed blocks, closure counts, stack restoration, and callee-saved registers. OS calls are intercepted; concurrent teardown is not modeled.
- The exact extracted original and fixed C routines were compiled with AddressSanitizer and UndefinedBehaviorSanitizer and run against real Linux pipe descriptors. The original closes the neighbor and leaves the owned descriptor open. The fixed version closes the owned descriptor and preserves the neighbor. Repeated release preserves a newly reused descriptor. LeakSanitizer is disabled because the host's ptrace sandbox prevents its thread scan.
- The final native disassembly was checked against the source correction. The IPA's changed member and prior fix bytes are verified during packaging.

Physical validation of the four-case regression now passed on the iPad. The diagnostic recorded graceful 0, abrupt 0, abrupt 19 and abrupt `0xc0000005` (an exit value, not an induced fault), followed by final PASS. Runtime `f438e6fd98da06f3` shows the children and diagnostic parent exiting cleanly. The captured interval has no protocol errors, read-request errors or unhandled native exceptions. This verifies the small guest-exit regression, not concurrent CEF teardown or BeamNG gameplay. One ownership-ledger CROSS trace remains for descriptor 196 during parent cleanup without a matching observed protocol error; it remains an audit lead rather than a proven new fault.

The CEF startup failure and BeamNG gameplay remain unresolved. This patch does not alter CEF's exit decisions, relax its timeouts, modify reported Vulkan features or change the diagnostic's expected exit codes. Other existing cache-lifetime and async-cancellation concerns are outside this narrow correction.

Files in `device-before/` preserve the failing diagnostic and matching runtime. `build.py` pins the prior IPA/native hashes, builds the replacement loop, runs the tests, and writes `Madeira-iPad-GuestExit-v2-Test.ipa`. `package-report.json`, `native-test-report.json` and `real-fd-test-report.json` record the results. Installation and signed-payload checks are recorded separately in `install-report.json` once complete.

Installation completed successfully according to the installer's device progress and completion log. An artifact check found that this CLI's `--output` file is byte-identical to its input IPA, despite its “Saved signed package” message. The CLI source installs from the signed staging bundle before exporting, so this does not negate the installation result. It does mean the local file named `Signed.ipa` is an input copy, not an independently verified signed artifact. The temporary signing stage was already removed. The report distinguishes the verified exported payload from verification of a distinct signed payload; the physical four-case regression passed as documented above.
