# Async cancellation cleanup correction — reviewed and installed; first iPad diagnostic stopped at pipe setup

The current GuestExit-v2 iPad captures reproduce a native null-link fault at req_cancel_async+0x158 (binary VA 0x100054f44, store to address 8) after both the full content launch and the CEF simple-page comparison. The full content launch first reached a MainGEUI timeout; the simple-page launch first reported TS_PROCESS_CRASHED. The cancellation fault is established during later cleanup, not established as the initial CEF failure.

Pinned server/async.c calls cancel_async and then accesses and relinks the async without retaining it. async_terminate explicitly permits thread_queue_apc to complete the operation synchronously and drop its last reference. The source correction retains tracked objects until restoration, attaches completion groups before callbacks, and holds a construction sentinel during enumeration. All three are needed for immediate completion. Restoration rereads the tracked head after each release because destruction can mutate other entries.

build.py extracts the pinned production function bodies into reduced host fixtures. ASan/UBSan reproduce the original heap-use-after-free; a keepalive-only negative control reproduces the completion-group assertion. The correction passes 81 lifecycle cases, including dead-thread synchronous completion, deferred completion, completion of earlier tracked operations, mixed paths, allocation failures, filters, and already-canceled operations. Every fixture-owned allocation is released. LSan is disabled because the host ptrace sandbox prevents its thread scan; this is explicit allocation accounting, not a full-process leak scan.

These are host source tests, not native iOS or device validation. AsyncCancel-v1 has now been signed and overlay-installed successfully; its first physical diagnostic stopped at pipe setup before cancellation. The candidate integrates the correction into only the 640-byte req_cancel_async function of the exact GuestExit-v2 executable. The full prologue, epilogue and compact unwind entry are preserved. The candidate native SHA-256 is f6ef9798133cfd487ee3decc83ec7cb0f762e2952b78b25967820a4efa1ec984. Its 148 complete-function Unicorn cases pass, and independent review found no blocking defect. Review adds 110 full-handler cases, 103 production-body ASan/UBSan cases and 32 cases using the actual native get_fd_user/grab_object helper instructions. Reports state their modeling limitations. A separate inherited assertion for overlapping existing cancellation groups is not fixed by this change. The separate CEF startup/painting problem remains unresolved.
