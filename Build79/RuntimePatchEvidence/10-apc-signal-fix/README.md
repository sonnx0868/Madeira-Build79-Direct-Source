# Madeira iOS system-APC signaling correction

The AsyncCancel-v1 iPad build failed two small tests before BeamNG. Pending ConnectNamedPipe signaled its event while OVERLAPPED.Internal remained STATUS_PENDING (0x103); GetOverlappedResult returned ERROR_IO_INCOMPLETE (996), unchanged after an alertable yield. A separate Chromium72-style inherited pipe passed preconnection/inheritance and initial exchanges, then returned a successful zero-byte IOCP read with its original status block still pending. Evidence is preserved in ../cef-ipc-staging/before-signal-fix/result.json.

The pinned iOS source skips Wine's cross-process task-port handoff. The native send_thread_signal nevertheless reads the resulting zero process trace port and returns failure. queue_apc rejects the system APC; destroying that unexecuted async APC can signal completion without the client callback ever publishing status/data. This explains the demonstrated class of premature completion, though full CEF causality remains to be tested.

The candidate changes only send_thread_signal's task-port acquisition to the current app's Mach task. Every Wine guest is a pthread in this one iOS app. Real Mach thread-right extraction, Darwin __pthread_kill, errors, right deallocation, and dead-thread handling remain intact. get_process_port and remote memory access remain unchanged: enabling those globally previously caused regressions. The correction affects signals sent through this helper, including system-APC SIGUSR1 and termination SIGQUIT. It does not fabricate signal success.

The 20-byte replacement differs in19 bytes, within [0x10006c32c,0x10006c340). The exact native candidate SHA-256 is1ae878fbc6ed1f2ffcc9febda14ad55bbffdb5a6efbe8c35cd10db6822c67a7b. All surrounding bytes, frame, prologue/epilogue and unwind metadata are unchanged. Independent review checked source/native equivalence and128 complete native function cases, covering live/dead PIDs, zero/nonzero old trace ports, Mach/kill success and failure, SIGUSR1/SIGQUIT and debug logging/ABI. Mach/libc helpers are instrumented; this is not physical signal delivery validation or a source APC-queue integration test.

The pinned source explicitly warns that an earlier iOS experiment saw __pthread_kill return success without its SIGUSR1 handler running. A separate CPU-window diagnostic therefore checks whether a pending read's status/data are published while the issuing thread executes no Wine API calls. Its two host runs and withheld-write control passed; its finite iteration window can produce timing-related inconclusive results. Success measures observable asynchronous publication, not identity of the underlying handler.

APC-Signal-v1 was signed and installed successfully. The actual signed staging bundle was retained and archived. Every native Mach-O section matches the reviewed candidate, all4404 CodeDirectory SHA-256 pages verify, and the CPU/TLS PE files are unchanged. This verifies the signed staging bundle delivered to the successful installer, not a binary extraction from the iPad or independent CMS trust validation. Physical retesting now passes all three Windows diagnostics: 48 rounds/192 cancellations with subsequent pipe reuse, 12 rounds per role of inherited IOCP traffic plus64KiB and peer closure, and correct status/data publication during the issuing thread's CPU-only window. All five logs have fresh device mtimes and verified hashes; all three suite child processes exited0. This establishes the tested completion paths on the iPad, not BeamNG or CEF UI success.
