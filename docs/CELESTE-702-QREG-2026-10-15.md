# Celeste build 702: STR-Q register-offset alias fault

Complete report `291f2823-5ff6-4228-bca1-41049a6c52a4`, 377,699 bytes,
Previous session, source `8b25f7c`, iPad14,6, received 16:35 +07.
At review time this was the only new build-702 report; the next server
report was still Celeste build701. A new Sundered report was requested.

## Confirmed progression and failure

The managed launch is isolated, WoW64 initializes, `[wine-mono-v1]` records
`state=linked`, and `libmono-2.0-x86.dll` loads. The runtime proceeds through
mscorlib, Microsoft.Xna.Framework and WineMono.FNA. The earlier missing-Mono
failure has been passed. `.dll.dll` probes are native/AOT discovery attempts;
they are not evidence that all of these managed assemblies are missing.

The first `[store-undecoded]` explicitly identifies a valid anonymous RW
alias and unsupported `0x3cb84a70` (STR Q16 register offset). Later stores use
`0x3cab4a70` (STR Q16,[X19,W11,UXTW]) and `0x3cb84a73` (STR Q19,[X19,W24,UXTW]).
At the terminal loop, host PC `0x1690d0684` writes `0x7105218000`, inside a
16 KB page of the existing anonymous JIT alias. X19 is the WoW64 base
`0x7100000000`. Wine initially reports RX, the guest SMC callback invalidates
and requests logical RWX, but the port correctly retains physical RX for
the dual map. Retrying the same undecoded vector store therefore faults
again. The existing redelivery guard logs **2,000 identical faults** and
terminates the application. This is a concrete unsupported store path,
not evidence of shader compilation, an FPS cap, or a need for another DLL.

## Correction

Add only the observed 128-bit SIMD register-offset store family to the
parent-owned native signal consumer. Do not edit FEX. Compute its effective
address from the saved base/index registers (UXTW, LSL, SXTW, SXTX and the
Q-form's optional shift4); validate that FAR is within its 16-byte store.
Require real NEON state, logical WRITE on both ends and full contiguous
existing RW alias coverage. A logical RX page is deliberately declined so
the existing guest SMC invalidation runs first. Copy Q0..Q31 (Q31 is real,
not XZR) through the RW alias; use the existing Mach continuation to advance
PC exactly4. Base/index registers and flags remain unchanged. No mapping,
mprotect, source-game patch, or new periodic profiler is introduced.

The limited Mach GPR array contains x0..x28: FP/LR address encodings decline
instead of reading out of bounds. SP as base and ZR as index are handled.
The surrounding alias writer retains its existing policy and counters;
this patch does not claim a general cure for translation coherency.

## Checks

`check-qreg-alias.py` assembles35 real instructions and executes the actual
helper, actual Mach dispatch branch and actual PC-advance statements. Cases
include the exact two terminal opcodes, W-index upper garbage, signed and
shifted offsets, SP/ZR/Q31, a fault within the latter bytes of a store,
canary bounds, read-only SMC-before-write, absent/discontinuous aliases,
unknown permissions, missing NEON, excluded loads/unallocated forms and
FP/LR rejection. All pass on the Windows host. The preceding234-case
RCPC2 test also passes. Native iOS compilation and device execution are
separate gates; no Celeste gameplay success has been measured yet.
